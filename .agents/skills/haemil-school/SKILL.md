# 해밀학교 프로젝트 전용 Skill

## 필수 참조
- 모든 작업은 시작 전 `PROJECT_SPEC.txt`와 이 `SKILL.md`를 반드시 먼저 확인한다.
- 모든 작업은 진행 중/완료 후에도 `PROJECT_SPEC.txt`와 이 `SKILL.md` 기준으로 정책 준수 여부를 재검토한다.
- 정책 충돌 시 우선순위는 다음과 같다: 사용자 최신 지시 > `PROJECT_SPEC.txt` > `SKILL.md`.

## 프로젝트 목적
- 해밀학교 학생 60명의 생활관비 후원을 위한 1:1 결연형 모금/운영 사이트를 구축한다.
- 단순 소개 페이지가 아니라 실제 운영 가능한 후원 신청, 입금 확인, 결연 완료 처리, 관리자 운영 기능까지 포함한다.

## 기술 스택
- Frontend: Next.js App Router, TypeScript, Tailwind CSS
- Backend: Next.js Server Actions, Next.js API Routes
- Database: Turso DB (SQLite 기반)
- Storage: Vercel Blob (이미지/영상)
- SMS: Solapi
- Deployment: Vercel
- Authentication: 고정 관리자 ID/PASSWORD (`/admin/login`)

## 페이지 구조
- 프론트 페이지:
  - `/` 홈
  - `/students` 학생 만나기
  - `/about` 학교 소개
  - `/project` 프로젝트 안내
  - `/gallery` 갤러리
- 각 페이지는 후원 맥락(현황, 스토리, CTA)을 유지하며, 모바일 반응형을 기본으로 구현한다.

## 관리자 구조
- 로그인 경로: `/admin/login`
- 회원가입 없는 단일 관리자 인증 구조를 유지한다.
- 관리자 핵심 기능:
  - 대시보드(후원/결연/전화 대상/최근 신청)
  - 결연 신청 관리(입금대기/입금완료/취소)
  - 발송 관리(Solapi 기반 문자 발송/이력)
  - 학생 관리(소개/이미지/손편지/결연 상태)
  - 갤러리 관리(사진/영상 업로드)
  - 설정(문자 수신자/발송 시간/관리자 연락)

## 후원 정책
- 학생 1명당 후원자 1명만 가능하다.
- 후원 방식은 일시후원(10만 원) / 정기후원(월 10만 원)을 유지한다.
- 자동 결제 기능은 추가하지 않는다.
- 후원 신청 후 관리자가 직접 연락하고, 수동 입금 확인으로 처리한다.
- 입금 완료를 결연 완료의 유일한 기준으로 사용한다.
- 입금대기 상태가 되면 다른 후원 신청은 불가하며, 취소 시 재신청 가능하다.

## 학생 공개 정책
- 학생 실명은 공개하지 않는다.
- 실제 학생 사진은 사용하지 않는다.
- 학생 프로필 이미지는 AI 카툰 이미지로만 사용한다.
- 공개 가능 항목은 닉네임/성별/학년/소개 문구로 제한한다.
- 손편지는 이미지 형태로 공개한다.

## 디자인 방향
- 따뜻하고 신뢰감 있는 분위기를 유지한다.
- 공익/교육 후원 사이트의 맥락을 유지한다.
- 너무 차가운 SaaS 느낌은 피한다.
- CTA 버튼은 명확하고 눈에 띄게 구성한다.
- 모바일 최적화를 우선한다.
- 여백을 충분히 사용한다.
- 카드 UI 기반 레이아웃을 사용한다.
- 접근성을 고려한다(명도 대비, 포커스, 대체 텍스트, 키보드 접근).

## 개발 규칙
- 관리자 페이지와 프론트 페이지를 모두 유지/구현한다.
- App Router 기반 구조를 유지한다.
- Turso DB를 사용한다.
- Vercel Blob을 사용한다.
- Solapi를 사용한다.
- 모바일 반응형 구현은 필수다.
- SEO 기본 요소를 유지한다.
- 실제 운영 가능한 후원 플로우를 훼손하지 않는다.

## 금지사항
- 학생 실명 노출 금지
- 실제 학생 사진 사용 금지
- 자동 결제 기능 추가 금지
- Google 로그인 추가 금지
- 기존 라우트 삭제 금지
- `PROJECT_SPEC.txt` 삭제 금지
- `README.txt` 삭제 금지
- mock 데이터 구조 임의 변경 금지
- 관리자 페이지 또는 프론트 페이지 중 하나만 남기는 구조 변경 금지
- Turso DB/Vercel Blob/Solapi를 대체하는 임의 스택 변경 금지(명시 지시 없을 때)

## 작업 보고 규칙
- 작업 완료 시 수정/생성/삭제 파일 목록을 반드시 보고한다.
- 주요 정책 반영 여부를 체크리스트 형태로 함께 보고한다.
- 테스트/검증을 수행했다면 결과를 함께 보고하고, 미수행 시 이유를 명시한다.
- 라우트/데이터 구조/정책 관련 변경이 있으면 `PROJECT_SPEC.txt` 정합성을 함께 보고한다.

## 상시 참조 규칙
- 앞으로 이 프로젝트의 모든 작업에서 `PROJECT_SPEC.txt`와 이 `SKILL.md`를 항상 참조한다.
- 신규 기능, 리팩터링, UI 수정, 데이터 변경, 관리자 기능 작업 모두 동일하게 적용한다.
